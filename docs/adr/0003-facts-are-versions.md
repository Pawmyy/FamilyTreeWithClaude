# Every fact is stored as versions, with one accepted

Families and documents disagree about names, dates and even parentage, and the record should hold the disagreement instead of silently overwriting it. So names, birth and death dates, sex, and every relationship are stored as versions of a fact; several versions can coexist, each saying who it is according to and which sources support it, and exactly one per fact is the accepted version that every view uses. Relationships are versions too, which means the shape of the family itself can be disputed.

## Considered Options

One value per fact with disagreement typed into notes (untraceable), and letting the whole tree be flipped between rival accounts (a much larger feature for a rare need). A computed credibility score was rejected: repeated family stories would count as independent evidence.

## Consequences

There are no logins yet, so "according to" is a name, not an account, and the edit log records what changed and when but not who. Notes, nicknames and photos stay single-valued. Removing something moves it to the edit log, from which it can be restored.
